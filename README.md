# Ollama UI

A lightweight ChatGPT-style web interface for [Ollama](https://ollama.com), served by nginx. Everything runs in Docker: Ollama itself runs in a container too. Image generation and upscaling run alongside it in a [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) container using Z-Image-Turbo, image editing in a second one using FLUX.2 klein 9B, and video generation in two more: LTX-2.3 22B (with audio) and Wan 2.2 TI2V 5B.

## Run

```sh
docker compose up -d --build
```

Then open http://localhost:3000.

The only host requirements are Linux, Docker with Compose, and an NVIDIA GPU with the [NVIDIA Container Toolkit](#gpu-setup).

The `ollama` service runs the chat models, and the `ollama-models` job pulls `qwen3:8b` on first start. To pull others, list them in a `.env` file next to `docker-compose.yml`, e.g. `CHAT_MODELS="qwen3:8b gemma3:12b"`, or pull one any time with `docker exec ollama ollama pull <model>`. Models are kept in the `ollama-models` volume.

Ollama listens on `127.0.0.1:11434` with host networking, so stop any Ollama already installed on the host first (`sudo systemctl disable --now ollama`), or the two will clash over the port. Models it had pulled aren't shared with the container and need pulling again.

The first `up` takes a while: it compiles stable-diffusion.cpp with CUDA (~15–30 min) and downloads ~27 GB of image model weights into the `image-models` Docker volume (~35 GB more with video enabled; see below). The video download runs separately, so image generation is available before it finishes. Later starts reuse both.

## Image generation

Pick the model under **Image** in the model picker and describe the picture you want. Images are generated by the `image-server` service (stable-diffusion.cpp running Z-Image-Turbo Q6_K, 8 steps) and saved in the chat like any other message. Image size is in Settings.

### Upscaling

Attach an image to the Z-Image model (no prompt needed) to upscale it 4× with an ESRGAN model. Pick the model under **Upscaler** in Settings: Faithful (the default) enlarges and cleans up without inventing detail, so faces and text stay intact, while Soft, Balanced and Sharp add progressively more GAN-generated texture. **Auto color-correct** stretches each color channel's levels before upscaling, which fixes washed-out contrast and color casts. Transparency is preserved.

### Editing

Pick the model marked **(edit)**, attach an image and describe the change, e.g. "make it night time" or "remove the person on the left". The `edit-server` service runs FLUX.2 klein 9B (Q8_0, 4 steps) and returns the result at the input's aspect ratio, about one megapixel. Without an attachment it generates from text like the Z-Image model. FLUX.2 klein 9B is under a non-commercial license.

## Video generation

Pick a model under **Video** and describe the clip. Attach an image to use it as the first frame (image-to-video); the video keeps its aspect ratio. Size and length are in Settings (default 1280 × 720, 5 seconds at 24 fps). There are two models:

- **LTX-2.3 (with audio)**, the `video-server` service: generates a matching audio track, so describe any sound you want (dialogue, music, ambience). It runs the 22B distilled model at Q3_K_S (8 steps, no CFG) with Gemma 3 12B as its text encoder, sized to fit a 16 GB GPU.
- **Wan 2.2 TI2V 5B**, the `wan-server` service: no audio, but much lighter and faster.

Expect generation to take minutes, not seconds; the Draft size is much faster for trying prompts. All the servers share one GPU, so run one generation at a time: the UI waits for each job before allowing the next, but two browser tabs or users generating at once can run the GPU out of memory. Videos are WebM (VP8 with PCM audio) and are stored in the browser's IndexedDB rather than localStorage, since each is several MB.

## GPU setup

Ollama and the image servers need GPU access from Docker, which requires the [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). On Ubuntu / Linux Mint:

```sh
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

The CUDA kernels are compiled for RTX 30-series cards (`sm_86`). For another GPU, set `SD_CUDA_ARCH` when building, e.g. `SD_CUDA_ARCH=89 docker compose build image-server` for RTX 40-series, or put `SD_CUDA_ARCH=75` in a `.env` file next to `docker-compose.yml` for a Tesla T4.

### GPU memory

The servers load their weights from the model files only while generating and release them afterwards (`--params-backend disk`), so idle servers use almost no RAM or VRAM, and they fit alongside Ollama on a 16 GB machine. Each job starts by reading its model from disk, so keep the `image-models` volume on an SSD. Before each image or video, the UI asks Ollama to unload any chat models so the two don't compete for VRAM; the next chat message reloads the chat model. You can turn this off in Settings if your GPU has room for both.

To run without image generation, start only the UI: `docker compose up -d --build ollama-ui`. Video is off by default because of its ~35 GB download. To turn it on, put `COMPOSE_PROFILES=video` in a `.env` file next to `docker-compose.yml`, or run `docker compose --profile video up -d`.

## Configuration

Environment variables (set in `docker-compose.yml`):

| Variable      | Default                  | Purpose                      |
|---------------|--------------------------|------------------------------|
| `OLLAMA_URL`  | `http://127.0.0.1:11434` | Where the Ollama API lives   |
| `SD_URL`      | `http://127.0.0.1:7861`  | Where the image server lives |
| `SD_EDIT_URL` | `http://127.0.0.1:7862`  | Where the edit server lives  |
| `SD_VIDEO_URL`| `http://127.0.0.1:7863`  | Where the LTX video server lives |
| `SD_WAN_URL`  | `http://127.0.0.1:7864`  | Where the Wan video server lives |
| `LISTEN_PORT` | `3000`                   | Port the UI is served on     |

### Without host networking (e.g. Docker Desktop on macOS/Windows)

Replace `network_mode: host` with a port mapping and point at the host gateway:

```yaml
    ports:
      - "3000:3000"
    extra_hosts:
      - "host.docker.internal:host-gateway"
    environment:
      OLLAMA_URL: http://host.docker.internal:11434
```

Do the same for the `ollama` service and set its `OLLAMA_HOST` to `0.0.0.0:11434`, so the UI container can reach it.

## Features

- Streaming responses with a stop button
- Markdown, syntax-highlighted code blocks with copy buttons
- Model picker populated from your installed models
- Chat history in the sidebar (stored in your browser's localStorage)
- Collapsible "thinking" output for reasoning models (e.g. qwen3, gemma4)
- Image attachments (upload or paste) for vision models
- Image generation with Z-Image-Turbo (stable-diffusion.cpp)
- Video generation with LTX-2.3 (with audio) and Wan 2.2
- System prompt and temperature settings
- Regenerate last reply
